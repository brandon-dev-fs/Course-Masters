# Add @@map Directive to StudentNote Model

## Problem Statement

All 15 database models in the Prisma schema use explicit `@@map` directives to map PascalCase model names to snake_case PostgreSQL table names. The `StudentNote` model is the only exception -- it is missing its `@@map("student_note")` directive, causing PostgreSQL to use the default PascalCase table name `StudentNote`. This inconsistency creates a naming mismatch that could cause confusion during direct database access, tooling integration, or future migrations.

## Scope

### In Scope

- Adding `@@map("student_note")` to the `StudentNote` model in the Prisma schema
- Generating and applying a Prisma migration that renames the existing `StudentNote` table to `student_note` in PostgreSQL

### Out of Scope

- Changes to any API endpoints, request/response shapes, or route handlers
- Changes to any frontend components, pages, or client-side logic
- Changes to the Prisma client usage in application code (Prisma client references the model name `StudentNote`, not the table name, so no application code changes are needed)
- Changes to any other models or their `@@map` directives
- Data migration or data transformation (this is a table rename only; all existing data is preserved)

## Requirements

### Functional Requirements

- FR-01: The `StudentNote` model in the Prisma schema must include a `@@map("student_note")` directive that maps the model to a snake_case table name in PostgreSQL.
- FR-02: A Prisma migration must be generated that renames the existing `StudentNote` table to `student_note` without data loss.
- FR-03: After the migration is applied, all existing `StudentNote` records must be intact and accessible through the Prisma client without any application code changes.
- FR-04: After the change, every model in the Prisma schema must have an explicit `@@map` directive mapping to a snake_case table name (no models rely on default PascalCase table naming).

### Non-Functional Requirements

- NFR-01: The migration must be non-destructive -- it must rename the table, not drop and recreate it.

## Systems-Level Architecture

### Components Involved

- **Prisma schema** (`server/prisma/schema.prisma`): The `StudentNote` model definition, where the `@@map` directive will be added.
- **Prisma migration**: A new migration file generated by `prisma migrate dev` that performs the table rename.

### Data Model Changes

Add an `@@map("student_note")` directive to the existing `StudentNote` model. No new models, fields, relationships, or enum values are needed. No existing fields or relationships change.

### API Changes

None. No endpoints are added, modified, or removed.

### Data Flow

This change has no runtime data flow impact. The Prisma client continues to reference the model as `StudentNote` in application code. The only change is the underlying PostgreSQL table name, which Prisma abstracts away from the application layer.

### Integration Points

- **Prisma ORM**: The Prisma client must be regenerated after the schema change so it references the new table name internally. This happens automatically as part of `prisma migrate dev`.
- **Existing StudentNote queries**: All existing Prisma queries using the `StudentNote` model (in student notes routes, any related includes) continue to work without modification because Prisma uses the model name, not the table name.
